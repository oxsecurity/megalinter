# Native Install Rules (`native_install`)

Native mode runs MegaLinter on the host without Docker. Every linter declares how it is installed natively with the linter-level `native_install` property (descriptors and `shared/*.megalinter-linter.yml`). The Docker `install` block stays the source of truth for Docker images and is **never changed** by native work: generated Dockerfiles must stay byte-identical.

The build (`.automation/build.py`) fails when a linter has no `native_install`, or when one of the 5 native platforms is neither supported nor explained.

## Platforms

`linux/amd64`, `linux/arm64`, `darwin/amd64`, `darwin/arm64`, `windows/amd64` (WSL is Linux; `windows/arm64` uses the `windows/amd64` assets). Every linter must list each platform either in `platforms` or in `unsupported` (with a user-facing reason ending with "Use Docker.").

## Properties

| Property                | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
|-------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `method`                | `pip`, `npm`, `gem`, `go`, `dotnet_tool`, `powershell_module`, `binary`, `runtime_provided`                                                                                                                                                                                                                                                                                                                                                                                           |
| `version`               | Version of the tool. Not needed for `pip`, `npm`, `gem` and `runtime_provided` (their `packages` carry the versions); required for the other methods. `"${ARG_NAME}"` reads the `ARG ARG_NAME=...` of the linter's `install.dockerfile`. `"${FROM_TAG:image/name}"` reads the tag of the `FROM image/name:tag` line (kept as written, `v` prefix included). A literal is allowed only when Docker has no pin (`latest`), and must carry a `# renovate: ...` comment on the line above |
| `packages`              | Packages of the package-manager methods. Default: `install.pip` / `install.npm` / `install.gem` of the linter (descriptor-level `install.npm` is added for npm). `${ARG}` references are resolved                                                                                                                                                                                                                                                                                     |
| `requires`              | `[{runtime: java, version: ">=21"}]`, runtimes from `native-runtimes.yml` (`python`, `node`, `java`, `dotnet`, `go`, `powershell`, `dart`, `php`, `perl`, `ruby`, `r`, `rust`, `swift`, `git`)                                                                                                                                                                                                                                                                                        |

| `executables`           | Command name to path inside the install dir, or `{launcher: java, args: [...]}` for jar/phar/script launchers. MegaLinter generates the shims. | `env`                   | Environment variables set for this linter only (`{{NATIVE_INSTALL_DIR}}` available)                                                                                                                                                                                                                                                                                                                                                                                                   |
| `linter_overrides`      | Linter properties replaced **only in native mode** (`cli_executable`, `cli_lint_extra_args`, `cli_executable_version`...). | `suggest`               | `runtime_provided` only: map `windows` / `darwin` / `linux` to the official install command of a **host-provided tool** that MegaLinter does not download (no portable, verifiable build): xmllint, swiftlint, cppcheck... MegaLinter looks for it on `PATH` and prints the command when missing                                                                                                                                                                                      |
| `provenance`            | How the lock generator verifies the download (see below)                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `allow_install_scripts` | npm/gem packages allowed to run install scripts: `[{package, reason}]`. Default: none                                                                                                                                                                                                                                                                                                                                                                                                 |
| `allow_source_build`    | `{reason}`: allows pip sdists / gem native extensions (needs a compiler)                                                                                                                                                                                                                                                                                                                                                                                                              |
| `platforms`             | Supported native platforms                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `unsupported`           | Map platform to reason                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `overrides`             | Map platform to a partial `native_install` replacing keys for that platform only                                                                                                                                                                                                                                                                                                                                                                                                      |

## Provenance (binary assets)

Pick the strongest mechanism the upstream offers, in this order:

1. `github_attestation: owner/repo`: GitHub artifact attestation (`gh attestation verify`)
2. `cosign: {identity, issuer}` / `sigstore`: keyless signature of the asset
3. `gpg: {keyring, signature_url}`: keyring stored in `.automation/native-keys/`
4. `checksums_url`: checksum file published by the same release (`{{VERSION}}` and `{{ASSET_NAME}}` available), possibly with `checksums_format: sha256sum|sha512sum`
5. `unverified: "<justification>"`: last resort, reviewed in the PR. The lock generator pins the sha256 on first download and fails on any later change of the same version

Package-manager methods are verified by the registry integrity data (PyPI hashes, npm `integrity`, NuGet/crates.io/RubyGems checksums) and need no `provenance`.

## Rules

- Prefer the official upstream release asset over building from source or a distribution package
- Check each URL exists (`curl -sIL <url>`) for the pinned version before writing it
- A tool without any usable Windows (or macOS) build is `unsupported` there, with the real reason
- Never use `curl | sh`, install scripts, `RUN` snippets or `sudo`
- Keep the Docker `install` block untouched
- Shared linters (`shared/*.megalinter-linter.yml`): put the common `native_install` in the shared file, platform/URL differences in the descriptor entry (shallow merge, as for the rest of the entry)
- The `/add-linter` and `/update-linter-version` skills must keep `native_install` and its lock in sync (`make native-lock`)

## Locks

`megalinter/descriptors/native-locks/<LINTER_KEY>.json` is generated by `.automation/native_lock.py` (`make native-lock`) from the descriptors, never edited by hand. The installer only downloads URLs and installs package versions that appear in the lock, after checking sha256.
