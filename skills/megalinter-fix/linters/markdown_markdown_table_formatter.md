## Fix instructions

markdown-table-formatter is a pure formatter: it checks that markdown tables are prettified (aligned pipes, consistent column padding, via the embedded markdown-table-prettify library). It reports no rule-based findings — a failure only means one or more tables are not formatted as the tool would write them.

- Preferred fix: let the tool rewrite the tables. Use the MegaLinter auto-fix described in the block above, or run it directly on the offending files: `npx markdown-table-formatter "**/*.md"` (accepts individual files, multiple files, or a glob expression).
- The tool's check-only mode is `-c` / `--check` (this is how MegaLinter detects unformatted tables without touching files); running the same command without `--check` updates the files in place.
- If column spacing looks wrong after formatting, adjust padding with `-p` / `--columnpadding <number-of-spaces>` (pass it through the linter arguments variable so check and fix stay consistent).
- Do not hand-align tables to match the expected output — running the formatter is always faster and exact.

## Inline disable

Wrap any table (or block of markdown) that must keep its current layout between ignore comments; the tool skips everything in between:

```markdown
<!-- markdown-table-prettify-ignore-start -->
| raw | table | kept as-is |
|--|--|--|
<!-- markdown-table-prettify-ignore-end -->
```

## Ignore via configuration

markdown-table-formatter has no configuration file and no ignore file: it only formats the files or glob expression given on the command line. To exclude files, use the MegaLinter-level filter variable listed in the block above, or use the inline ignore comments for individual tables. Example in `.mega-linter.yml`:

```yaml
MARKDOWN_MARKDOWN_TABLE_FORMATTER_FILTER_REGEX_EXCLUDE: "(docs/generated/|CHANGELOG\\.md)"
```

## When disabling is legitimate

- Tables generated by other tools (e.g. terraform-docs, doc generators) whose output would be endlessly re-flagged — wrap them in the ignore comments, as the README itself recommends for such integrations.
- Tables with very wide cells where reformatting produces unreadably long lines you intentionally keep compact.
- Markdown dialects or renderers where the prettified pipe alignment conflicts with other tooling that rewrites the same tables (formatter wars): pick one formatter and exclude the files from the other.

Disabling the linter globally at MegaLinter level (`DISABLE_LINTERS`) is the last resort — prefer inline ignore comments or file exclusion.
