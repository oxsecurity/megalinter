## Fix instructions

actionlint is a static checker for GitHub Actions workflow files: it validates `${{ }}` expression
syntax and types, `runs-on:` runner labels, action inputs/outputs, glob patterns, CRON syntax,
permissions, credentials, deprecated workflow commands, script injection risks, and runs shellcheck
(and pyflakes) on `run:` scripts. It has no auto-fix: correct each finding manually.

- Expression/type errors: fix the `${{ }}` syntax, use an existing context property, or convert
  types explicitly (e.g. wrong property name on `github`, `steps.<id>.outputs`).
- Unknown runner label in `runs-on:`: use a supported GitHub-hosted label, or declare your
  self-hosted labels in the configuration file (see below).
- Action input/output errors: add missing required inputs, remove unexpected ones, and reference
  only outputs the action actually defines via `steps.<step_id>.outputs`.
- shellcheck findings in `run:` steps: fix the shell script itself (quote variables, etc.).
- "potentially untrusted input" (script injection): never interpolate values such as
  `github.event.pull_request.title` directly in a script; pass them through an intermediate
  environment variable (`env:`) and reference the variable in the script.
- Hardcoded credentials in `container:`/`services:`: move them to secrets and reference
  `${{ secrets.NAME }}`.
- Deprecated workflow commands (e.g. `set-output`): switch to the current `$GITHUB_OUTPUT` /
  `$GITHUB_ENV` file-based equivalents.

## Inline disable

actionlint has no inline suppression comment of its own in workflow files, and shellcheck
`# shellcheck disable=...` directives inside `run:` scripts are not reliably honored. Suppress
findings instead through the configuration file `paths:` ignore patterns (below) or by adding
repeatable `-ignore 'regex'` CLI arguments (RE2 regex matched against error messages):

```text
actionlint -ignore 'label ".+" is unknown' -ignore '".+" is potentially untrusted'
```

Pass such flags through the MegaLinter arguments variable listed in the block above.

## Ignore via configuration

Place the configuration file in the `.github/` directory (generate a skeleton with
`actionlint -init-config`). Declare self-hosted runner labels and strict `vars` checking, and
filter error messages per file with glob-keyed `paths:` ignore regexes:

```yaml
self-hosted-runner:
  labels:
    - linux-multi-gpu
config-variables:
  - DEFAULT_RUNNER
paths:
  .github/workflows/**/*.{yml,yaml}:
    ignore:
      - 'shellcheck reported issue in this script: SC2086:.+'
  .github/workflows/release.yaml:
    ignore:
      - 'the runner of ".+" action is too old to run on GitHub Actions'
```

Paths use `/` as separator and are matched relative to the repository root. There is no separate
ignore file; use `paths:` ignores or the MegaLinter filter-regex variable to exclude whole files.

## When disabling is legitimate

- Self-hosted or third-party (larger) runner labels unknown to actionlint: declare them under
  `self-hosted-runner.labels` rather than ignoring the error.
- shellcheck style findings (e.g. SC2086) in short inline scripts where quoting is intentional and
  inline directives are not honored: ignore the specific SC code via a `paths:` regex.
- "runner of action is too old" on actions you cannot upgrade yet (pinned third-party actions):
  ignore the exact message for the affected workflow file only.
- Workflow files generated by external tooling that you cannot edit: exclude them via a scoped
  `paths:` ignore or the filter-regex variable.
- Disabling the whole linter at MegaLinter level is the last resort; prefer the scoped mechanisms
  above.
