## Fix instructions

prettier is an opinionated formatter, not a rule-based linter: an error on a YAML file simply means "this file is not formatted the way prettier would print it". Do not hand-edit spacing to chase individual findings — run the formatter and let it rewrite the file.

- Preferred fix: enable MegaLinter auto-fix (see the `APPLY_FIXES` instructions above), or run `prettier --write <file.yml>` locally to reformat in place (comparable to the `eslint --fix` workflow).
- To see which files need reformatting without changing them, run `prettier --check .`: unformatted files are listed with a `[warn]` prefix followed by `Code style issues found in N files. Run Prettier with --write to fix.` (exit code 1 means issues found, 2 means prettier itself errored). Use `--list-different` instead to get only the file names.
- If a file keeps failing after `--write`, the check and the fix are probably not using the same configuration: make sure the config file resolved by MegaLinter (`YAML_PRETTIER_CONFIG_FILE`) matches the one used locally.

## Inline disable

Place a `# prettier-ignore` comment on the line immediately above a YAML node to keep that node's original formatting:

```yaml
# prettier-ignore
key  : value
hello: world
```

Here `key  : value` keeps its original spacing, while `hello: world` is still formatted normally.

## Ignore via configuration

To exclude whole files, add gitignore-syntax patterns to a `.prettierignore` file at the repository root (version-control directories and `node_modules` are already ignored by default):

```text
# generated manifests
dist/
**/generated-*.yaml
```

To change how YAML is formatted instead of ignoring it, set options in the prettier config file (`.prettierrc`, `.prettierrc.json`, `.prettierrc.yml`, `prettier.config.js`, or a `prettier` key in `package.json`). Options relevant to YAML:

- `printWidth` (default 80): preferred line length used for wrapping
- `tabWidth` (default 2): spaces per indentation level
- `useTabs` (default false): indent with tabs instead of spaces
- `singleQuote` (default false): prefer single quotes over double quotes
- `proseWrap` (default `preserve`): how text is wrapped — `always`, `never`, or `preserve`

Use the `overrides` section to scope options to YAML files only, via a `files` glob (an optional `excludeFiles` can carve out exceptions):

```json
{
  "overrides": [
    {
      "files": "*.{yml,yaml}",
      "options": { "printWidth": 120, "singleQuote": true }
    }
  ]
}
```

## When disabling is legitimate

- The YAML is generated by a tool (exported manifests, lock-style files): reformatting creates endless churn against the generator — list those paths in `.prettierignore`.
- The file mixes YAML with a templating language, such as Helm chart templates with `{{ ... }}` expressions: prettier's YAML parser can break or mangle the template syntax — ignore those directories.
- prettier's output conflicts with a stricter yamllint configuration also active in the repository (line length, quoting, indentation): align the two configurations first; if they cannot agree, keep only one tool authoritative for formatting.
- Only fall back to the MegaLinter tuning variables from the section above (`YAML_PRETTIER_FILTER_REGEX_EXCLUDE`, `YAML_PRETTIER_DISABLE_ERRORS`, `DISABLE_LINTERS`) as a last resort, when file-level ignores cannot express the exclusion.
